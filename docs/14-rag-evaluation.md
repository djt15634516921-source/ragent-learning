# D14：固定问题评估与排错

目标：把“某一次回答正确”变成可重复的检查，能够判断问题出在资料准备、检索、模型输入还是生成回答。截至 2026-11-01，已有用户手动提问观察，发现了错引和收费幻觉，并开展了修正与独立测试；完整十题独立基线尚未完成。

## 先准备资料

1. 在知识库页新建“D14 固定评估”，避免旧聊天和旧资料干扰。
2. 上传 `docs/examples/rag-eval/` 中的五份 Markdown 文件，分别解析、按 800/120 切分并向量化。它们都很短，默认切分参数下每份应为 1 块。
3. 保留默认 topK=4、minScore=0.35 和现有模型配置，先记录基线，不同时调多个参数。
4. 聊天页选择“D14 固定评估”，确认模式显示为“知识库问答”。每道题点击“新建会话”，使用独立会话，避免上一题答案成为下一题的历史提示。

只上传上述五份资料。题目、预期答案和评估记录放在资料目录之外，不要上传本文件或 `docs/evaluation/rag-baseline.json`，否则会把答案表当作知识来源。

其中青禾项目、月泉办公空间是干扰资料：它们包含相近的名称和口令场景，但事实属于其他对象。需要正确区分“星河的验收口令”和“青禾的验收口令/办公空间门禁口令”。

## 每道题怎样判断

先在页面回答下方展开资料来源，再对照原文；有疑问时用已有 `/api/knowledge-bases/{knowledgeBaseId}/search` 独立接口核对。页面返回的 sources 就是当次生成使用的片段快照；单独再检索得到的结果需单独记录，不混写成同一次请求。

1. **证据是否命中**：Q01—Q08 返回的片段正文是否确实包含题目需要的全部证据。只看到正确文件名还不够，大文件的其他片段可能没有所需事实。Q08 必须有两份资料的证据。
2. **回答是否正确完整**：事实值、单位、对象都要对。Q06 回答“两个工作日内解决”与原文“首次回复”不是同一件事。答案措辞可以不同，不用逐字匹配整句。
3. **引用是否支持结论**：`[1]` 应指向返回列表的第 1 个片段，并且那块正文支持对应事实。页面显示四个来源不代表所有来源都被答案实际引用，也不代表引用事实已经自动核验。
4. **缺少资料时是否诚实**：Q09/Q10 可能命中负责人或工单相关片段，但里面仍没有号码或价格。正确表现是说明缺少资料；不要机械要求来源必须为空。

源文件不预先规定 chunkId、分数或精确排名：编号由数据库分配，分数由实际 Embedding 产生。先记录真实观察，再分析问题。

## 根据失败位置查代码

| 观察到的问题 | 先查什么 |
| --- | --- |
| 上传了却无法检索 | 解析/切分/向量化状态，知识库选择，当前模型 profile |
| 正确证据没有出现在 sources 中 | `KnowledgeRetrievalServiceImpl.search`、`KnowledgeVectorMapper.search`，检查范围、版本、阈值、TopK 和字符预算 |
| sources 有正确证据，模型却答错对象或事实 | `ChatServiceImpl.modelQuestion` 组织的资料、提示词、聊天模式；再判断是否属于模型生成问题 |
| 回答正确但引用的块不包含事实 | 记录为引用问题，核对 sources 顺序与答案引用编号 |
| 普通聊天编造了资料事实 | 先确认是否进入知识库模式，不用普通聊天结果计算本次评估 |
| 单个问题正确，追问“它呢”失败 | 记录为后续问题改写用例；本轮固定十题使用独立完整问题，不用新会话伪装成已支持追问改写 |

基线完成后再对失败样本做单一改动，例如调整一个阈值，并用同一份资料、题目与模型复测。保留改动前后的结果，避免仅凭一条回答判断改进。

## 首轮观察：回答正确与引用正确需要分开

实际记录见 [2026-11-01-first-observation.json](evaluation/2026-11-01-first-observation.json)。用户的三次提问处于同一个 `chat-D1401` 会话；Q01 是第一轮，手机号和暗号两题分别带有一轮、两轮历史。题目中两题的实际措辞也与固定题略有不同，已在报告保留原始问法，不能把三次观察计为十题独立基线完成。

手机号那轮的回答正确说明了资料未提供号码，但还写出“验收负责人是林老师[1]”。数据库中当次来源顺序为：

1. `05-月泉办公空间.md`，相似度约 0.45137，不含林老师。
2. `01-星河项目验收.md`，相似度约 0.41558，包含负责人林老师。
3. `02-月泉工单规则.md`，相似度约 0.39562。
4. `04-青禾项目验收.md`，相似度约 0.39397。

因此当前可以确认：正确的负责人证据已被检索到，回答中的事实与拒答正确，但引用编号错误。前端显示顺序与数据库保存顺序一致，本次没有证据表明页面排序造成了错引。

引用编号应以本次结果为准，不把旧编号硬改成[2]。若单独检查历史影响，应在新会话重放原先完全相同的短问题。若改成固定 Q09 完整问法，则属于另一个问题表达的测试，不能仅归因于历史条件。原失败样本仍作为同会话场景的问题保留。

代码中 `ChatMemoryRepository.loadRecentMessages` 会将旧回答正文连同 `[1]` 这样的引用送入历史，但不会把旧来源快照一起作为历史元数据传给模型；当前 sources 又按本轮排序重新编号。旧编号是否干扰了新一轮生成是待验证假设，尚不能据此断言根因或宣称修复完成。

## 收费问题失败：命中相关资料不等于有答案

实际失败记录见 [2026-11-01-fee-hallucination.json](evaluation/2026-11-01-fee-hallucination.json)。用户在已有八轮提问的同一会话中问 Q10，模型给出“需支付50元[1]”。只读核对确认：当前四份资料快照都没有收费信息，先前助手回答也没有50元，被引用的工单规则只提供编号、首次回复时限和超时联系人。

本次可以定位到生成缺乏证据的问题。不能因为工单规则排第一、相似度约0.686就接受金额，也不能将原因直接归为历史中已有50元。来源列表非空时仍可能没有所问事实，后端的“无命中直接拒答”分支覆盖不到这一类情况。

针对该失败，知识库模式的输入改为显式提供 citationId、文件名和正文；相似度/内部编号继续保留在页面响应与来源快照中。知识库提示词补充逐项检查事实、相关性不等于证据、缺少具体值时明确无法确定等约束。首次尝试仅给历史助手消息加不可信标记，真实模型污染历史复测仍失败，因此最终改为在知识库生成请求中用占位消息隔离旧助手正文，保留近期用户问题用于理解上下文。数据库历史正文与快照不改写，普通聊天继续使用原完整历史与基础提示词。

这属于输入组织和提示词修正，不是独立的事实核验器；修正结果需以实际回归与真实提供方检查为准，不能仅凭新增了提示词宣布所有幻觉已解决。旧收费失败和手机号错引样本均继续保留。
